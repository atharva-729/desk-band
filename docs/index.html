Desk Band

Can a phone lying on a table tell which spot you knocked, so any table becomes an instrument with no extra hardware?

81%
Right on 4 spots of the same wooden table, tested on knocks recorded separately from the ones it learned from. Random guessing gets 25%. How it was measured ↓
  • Listen and feel: the phone's microphone hears each spot's own sound, and its motion sensor feels which way the jolt came from.
  • Learn in a minute: the phone asks for knocks on each spot in a random order, and a tiny model trains in the browser. No app, no cloud, no AI service.
  • Play: each knock becomes a note on the laptop (drums, dhol, marimba, chords, a pentatonic scale) within about 60 ms.
  • Any phone, any table: nothing to stick on or plug in, just a web page. What's built ↓

The data

  • One recording, 120 knocks: an iPhone flat on a wooden table, 4 spots about 20 cm from it, 15 knocks per spot, done twice in two different orders.
  • Train on one pass, test on the other (and the reverse), so the score never comes from knocks the model has already seen, or from the order they were knocked in.
  • What the model gets per knock: 18 sound bands from low to high pitch plus loudness (mic), and 7 jolt numbers (motion).

What accuracy costs

More teaching knocks, small gains

Same 4 spots, model trained on a random 4–15 knocks per spot (averaged over 30 draws), tested on the other pass.

Listening longer, more accurate but slower

The app's Response setting: how long after the knock the phone keeps listening. Delay = the phone's listening delay, before Wi-Fi and speakers.

  • 15 knocks per spot is the sweet spot: a minute of teaching for 4 spots. Below 6 it drops faster (72% at 4).
  • The default "Balanced" setting gives up 3 points to save about 23 ms, which a player notices more.
  • Clean labels matter more than more knocks. If one knock is counted twice while teaching, every later label slips by one spot: on these same knocks, that drops the fit from 89% to 26%. The app now ignores a second detection within 250 ms while teaching.
That is the result. Everything below is the how.

How it works

knock ─► phone mic (high-pass, onset detector) ─► ~60 ms snippet ─► 18-band spectrum shape + loudness ─┐
      └► phone motion sensor (jolt around the knock) ─► 7 direction/strength numbers ──────────────────┴► logistic regression
                                                                         ─► {spot, confidence, how hard} ─► laptop ─► sound / MIDI
  • Phone page: mic with echo cancellation, noise suppression and auto-gain all off; an adaptive noise floor finds each knock; up to ~8 knocks a second.
  • Model: multinomial logistic regression written by hand in plain JavaScript (static/core.js), trained on the phone in a fraction of a second. On this recording it beat nearest-centroid (~70%) and 3-nearest-neighbours (~65%).
  • Laptop page: every sound is synthesised in the browser (no samples), and the same knocks can drive GarageBand or Ableton over MIDI.
  • Server: Python standard library only. HTTPS for the phone (browsers need it for the mic and motion sensor) and a QR code to join.

What's built (v0.3)

  • 4, 5, 6 or 8 pads, each with a name ("laptop lid", "book"). Training is kept per pad count.
  • Kits: drums, desi percussion (dhol, tabla, ghungroo), marimba, melody, chords, your own chords, and Pentatonic: any key of C D E G A, major or minor, single notes or power chords. It's built so any order of knocks sounds fine, and 5 pads is exactly one octave.
  • Check accuracy: 2 prompted knocks per pad, in a random order, scored and never learned.
  • Fix it while playing: tap the right pad on the phone after a wrong note and it learns from that knock.
  • Explainer panel: the knock's waveform, each spot's fingerprint with this knock drawn over it, and how sure the model was.
  • Session log: every knock is logged on the laptop, and a script reads it back: which mic was used, double knocks, how loud each pad was, whether the labels line up.

Live play and limits

  • Live on 5 pads (4 table spots + the laptop lid): roughly 75% right by feel. That's an impression, not a measured number; a full Check round wasn't run. The log showed clean labels, and the confused pads were the ones knocked softly (about 4× the detection level, against 14× for the best pad).
  • Training is per setup: moving the phone or the laptop changes each spot's sound. A quick-recalibrate round is the next step if this is picked up again.
  • One phone can't split two knocks at once. Chords come from one pad strumming a chord.
  • Lag: ~60 ms of listening plus Wi-Fi and speakers. Fine for playing along, noticeable to a drummer. Bluetooth speakers add 150–250 ms.
  • Tested on one iPhone and one table. Android, other tables and next-day reuse are untested.
  • Earlier offline analysis (Python, a larger motion feature set) gave 66% motion, 76% mic and 82% both on the same recording. The numbers on this page come from the browser's own smaller feature set, which is what the app actually runs.

Prior art

  • Mogees (2014): any surface as an instrument, with a contact sensor plugged into the phone.
  • Vibrative (2012): typing on a table with an iPhone 4's accelerometer, about 80%.
  • Desk Band's angle: no accessories, mic and motion together, in a plain web page.

Run it

git clone https://github.com/atharva-729/desk-band && cd desk-band
python3 server.py      # laptop: http://localhost:8000   phone: scan the QR code on the laptop page
node tests/test_core.js

Phone and laptop on the same Wi-Fi. The phone warns that the certificate is self-signed: Show Details → visit. Lay the phone flat, press Teach all spots, then Check accuracy, then Play. Source: github.com/atharva-729/desk-band (MIT).
